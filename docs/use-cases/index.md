# Use cases

A use case is a whole example with its own data: the objects, the numbers, and the question they answer. The [tutorial](../tutorial/index.md) teaches the exchange. A [guide](../guides/index.md) teaches one mechanism. A use case shows the mechanisms at work on a dataset, so you can judge whether CESDM fits a situation like yours.

| Case | What it shows | Read it if |
|---|---|---|
| [Bookshelf: an EAR example](bookshelf.md) | The engine on a schema that is not energy: an author, a book, and the link between them | you want to see what the engine does without CESDM, or use it for another domain |
| [Living lab: survey and meter data](living-lab.md) | Social-science answers and engineering measurements on the same households, as an extension of `cesdm/schemas/base` | your project combines energy assets with data from another discipline |
| [Kundur's two-area system](kundur.md) | A textbook network for power flow and dynamics, with numbers that can be checked against the book | you want a published benchmark to test an adapter or a solver against |
| [Use TYNDP and PyPSA data](tyndp-pypsa.md) | ENTSO-E TYNDP 2024 scenarios and a PyPSA nodal network, already converted to CESDM | you need a real European system as a common starting point |
